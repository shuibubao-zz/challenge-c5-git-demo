| 项 | 内容 |

| 怎么改的 | 见下表 |
| 级别 | 官方模板 |

| starter 原样 | 我改成了 | 为什么 |
|---|---|---|
| 只在装了 `markdown` 库时可用 | 加 `md_lite.py` 零依赖引擎，缺库自动降级 | "能跑"不该依赖运气；换台机器没库就跑是这类工具最常见的死法 |

| 无测试 | `selftest.py` 20 项 + `tests/test_smoke.py` 8 项 | 没有断言就没有"等价"可言 |

## 二、公众号限制规则：每条都标了依据级别

这是最容易被质疑的部分——**说"公众号会剥离 class"很容易，证明它很难**。
完整摘录（逐字原文 + 4 处官方口径冲突的裁定 + 诚实清单）在仓库的 `docs/official-evidence.md`，
核验脚本 `tests/verify_official_quotes.py` 可联网复核这些原文是否还在页面上（2026-11-03 实测 10/10 通过）。

### 有官方明文依据（L1）

| 结论 | 官方原文（逐字） | 出处 |
|---|---|---|
| `<script>` 被去除 → MathJax/KaTeX 必然失效 | "此处会去除JS" | [新增草稿接口](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html) `content` 字段 |
| 外部图片链接被过滤 → 图片必须内嵌 | "外部图片url将被过滤" | 同上 |
| 正文有字数/体积上限 | "必须少于2万字符，小于1M" | 同上 |
| 图片格式仅 png/jpeg/jpg/gif，**不含 svg** | "图片（image）: 10M，支持bmp/png/jpeg/jpg/gif格式" | [上传永久素材](https://developers.weixin.qq.com/doc/service/api/material/permanent/api_addmaterial) |
| 单张图片大小 | "文件大小限制：图片2MB/视频10MB" | [新增临时素材](https://developers.weixin.qq.com/doc/service/api/material/temporary/api_uploadtempmedia) |

> **必须说清的边界**：以上出自**服务端接口文档**，证明的是"通过 API 提交图文时平台怎么处理"，
> 与"编辑器里 Ctrl+V 粘贴 HTML 会怎样"**不是同一机制**。它只能作为强旁证，不能当作编辑器白名单。

### 查不到官方出处、明确标注"未找到"（L3 实测）

`<style>`/`class` 被剥离、`<h1>` 被征用、`<div>` 渲染不稳、`<pre>` 被压成一行——
这 4 条我检索了开发者文档全站，**没有找到任何官方条文**（微信从未公开编辑器 HTML 白名单）。
处理：在 `references/wechat_restrictions.md` 里逐条标"未找到官方出处 + 实测"，并给读者可自行验证的步骤，**不伪造出处**。

### 被自己证伪、已删除的一条

v1 曾写"单篇不超过 100 张图片"。**这个数字没有任何官方来源**，属我把印象当成了事实。
已从文档与检查器删除，公开交代勘误，并写进核验脚本的回归护栏：该短语今后若不带"已删/查无出处"标记重新出现，脚本直接报错。

## 三、第三方思路与代码

| 来源 | 借了什么 | 怎么改的 | 级别 |
|---|---|---|---|
| `doocs/md`、`mdnice` 等 Markdown→公众号项目 | "样式全部 inline、禁用 class"的思路 | **未复制代码**，实现独立（本项目用 `<section>`，未沿用其模板） | L4 旁证 |
| matplotlib `mathtext` 官方文档 | 公式渲染方案（不需要本机装 LaTeX） | 直接调用其 API；**白底深字**是为公众号深色模式改的（原方案透明底在深色模式会隐形） | 官方文档 |
| Python 标准库 `argparse` / `pathlib` / `base64` / `re` / `dataclasses` | CLI 与路径、编码处理 | 标准库用法，未改写 | 官方文档 |
| Python-Markdown + BeautifulSoup4 | 作为**可选解析引擎** | 要求与自研引擎产出**字节一致**（selftest 有断言） | 各自项目 License |
| Claude / WorkBuddy skill-creator | 技能目录约定、官方打包/校验脚本 | 遵循约定，`SKILL.md` 保留 `agent_created: true` | 官方文档 |

### 明确没借、但常被误认为同源的东西

- **微信官方 HTML 白名单**：不存在公开版本。任何声称"这就是官方白名单"的清单都不可信——包括本项目的规则表，请你按标的依据级别自行判断。
- **排版 CSS 数值**：正文 16px / 行高 1.75 / 段间距 12px / 图片 `max-width:100%`，是我自己调的，不是从某个模板抄的。审美类选择无对错，欢迎改。

## 五、我对"拿来"的三条自我约束

1. **凡是借来的，写清从哪来、改了什么**——只写"参考了 XX"等于没写。
2. **凡是"上限/通过率/尺寸"类数字，必须当场给出处或当场标注"无出处，仅印象"**（这条是被 C4B 那次"100 张"打醒的）。
3. **合法不等于合适**：starter 的"自动装依赖"是常见的开源做法，但它替用户做了决定，所以删掉。
